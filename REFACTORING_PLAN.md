# План упрощения программы

## 1. Цель рефакторинга

Сделать код похожим на последовательное выполнение лабораторной работы, а не
на универсальную библиотеку:

- каждый этап запускается отдельно;
- `main.py` последовательно запускает все этапы;
- вариант, пути и остальные постоянные значения не передаются через аргументы;
- расчётные формулы остаются видны в коде;
- повторяющийся и неиспользуемый код удаляется;
- комментарии и строки документации пишутся на русском языке только там, где
  нужно объяснить формулу или нетривиальное решение.

Ориентир по объёму — сократить рабочий код примерно с 1250 до 700–850 строк
без изменения численных результатов и графиков отчёта.

## 2. Предлагаемая структура

```text
main.py
lab_common.py
1_statistics.py
2_sequence_plot.py
3_autocorrelation.py
4_histogram.py
5_distribution.py
6_generator.py
7_generated_analysis.py
8_comparison.py
tests/
  test_lab.py
```

Каждый файл этапа содержит функцию `run()` и обычную точку входа:

```python
def run() -> None:
    ...


if __name__ == "__main__":
    run()
```

Благодаря этому возможны оба варианта запуска:

```bash
python 3_autocorrelation.py
python main.py
```

`main.py` не выполняет расчёты самостоятельно. Он только импортирует восемь
функций `run()` и вызывает их в правильном порядке.

## 3. Что считать постоянными значениями

Аргументы командной строки для этой работы не нужны. Из `main.py` следует
удалить `argparse`, а известные значения записать как константы в
`lab_common.py`:

```python
VARIANT = 29
DATA_FILE = Path("data/29_data.txt")
RESULTS_DIR = Path("results")
SAMPLE_SIZES = (10, 20, 50, 100, 200, 300)
CONFIDENCE_LEVELS = (0.90, 0.95, 0.99)
LAGS = range(1, 11)
Q = 0.25
SEED = 29
GENERATED_SIZE = 300
```

Не следует фиксировать уже вычисленные `t1` и `t2`: их расчёт по исходным
моментам является содержательной частью лабораторной. При этом функция их
расчёта не должна принимать лишние настройки — она использует установленное
для варианта значение `Q`.

## 4. Содержание файлов этапов

### `common.py`

Оставить только то, что действительно применяется несколькими этапами:

- перечисленные выше константы;
- чтение 300 исходных значений варианта 29;
- создание каталогов для результатов;
- две-три базовые статистические функции, если без них возникает дублирование.

Проверки должны быть короткими: правильный номер варианта, ровно 300 конечных
неотрицательных чисел. Возможность передать другой вариант не нужна.

### `1_statistics.py`

- среднее, несмещённая дисперсия, СКО и коэффициент вариации;
- доверительные интервалы;
- расчёт для шести объёмов выборки;
- запись формы 1.

Формулы располагаются рядом с этапом, а не прячутся за большим количеством
универсальных функций и строковых ключей.

### `2_sequence_plot.py`

- чтение исходных данных;
- построение одной ломаной исходной последовательности;
- короткий вывод в терминал.

Отдельный текстовый файл с выводом второго этапа не создавать: тот же вывод
уже присутствует в отчёте.

### `3_autocorrelation.py`

- одна функция расчёта автокорреляции;
- расчёт сдвигов 1–10;
- CSV-таблица и график-ломаная;
- вывод о сравнении с границей `±1.96 / sqrt(300)`.

### `4_histogram.py`

- 18 интервалов по правилу `ceil(sqrt(n))`;
- интервальный ряд в CSV;
- гистограмма частот;
- короткий вывод в терминал.

### `5_distribution.py`

- расчёт начальных моментов;
- обоснование выбора закона `H2` по коэффициенту вариации;
- расчёт `t1` и `t2` при фиксированном `q = 0.25`;
- проверка теоретических моментов;
- возврат параметров через компактный `NamedTuple` либо обычный кортеж.

Текущий класс с несколькими свойствами можно убрать, если после рефакторинга он
не делает код понятнее.

### `6_generator.py`

- получение `q`, `t1`, `t2` из этапа 5;
- генерация 300 значений методом обратного преобразования;
- сохранение `generated.txt`.

Постоянную блок-схему не нужно каждый раз рисовать программой. Готовое
изображение следует перенести в ресурсы отчёта, после чего удалить код
построения блок-схемы из `plots.py`.

### `7_generated_analysis.py`

- загрузка либо воспроизводимая генерация последовательности с `seed = 29`;
- форма 2;
- график значений;
- гистограмма с плотностью `H2`;
- автокорреляционная таблица и график.

Этап должен одинаково работать как после этапа 6, так и при отдельном запуске.
Проще всего каждый раз повторять детерминированную генерацию, а не требовать
наличия промежуточного файла.

### `8_comparison.py`

- форма 3;
- коэффициент корреляции Пирсона;
- сравнительные графики последовательностей, гистограмм, плотности и
  автокорреляций;
- краткая итоговая сводка в терминале.

При отдельном запуске этап самостоятельно читает исходные данные и повторяет
генерацию с фиксированным seed.

## 5. Что удалить

После переноса логики удалить:

- `argparse` и параметры `--input`, `--out-dir`, `--seed`;
- длинный перечень путей и сообщений из текущего `main.py`;
- `src/plots.py` и `src/report_tables.py` как общие склады несвязанных функций;
- семь почти дублирующих файлов `stage_*_summary.txt` и функции их создания;
- генерацию неизменной блок-схемы при каждом запуске;
- обобщённые параметры функций, которые в работе всегда имеют одно значение;
- повторные преобразования уже проверенного массива в `numpy.ndarray`;
- проверки гипотетических ситуаций, невозможных для зафиксированного варианта,
  если они не защищают важную формулу от деления на ноль.

CSV-таблицы, `generated.txt` и изображения, используемые в отчёте, необходимо
сохранить.

## 6. Правила комментариев

Все английские docstring заменить русскими либо удалить. Комментарий нужен в
трёх случаях:

1. пояснение разницы между дисперсией с делителем `n - 1` и моментной
   дисперсией с делителем `n`;
2. объяснение выбора фазы и обратного преобразования в генераторе `H2`;
3. объяснение прочерка в форме 3 при делении на автокорреляцию, близкую к нулю.

Не нужны комментарии вида «строим график», «создаём массив» или «сохраняем
файл»: это уже видно из команды. Названия функций и переменных оставить
английскими, поскольку это код Python; пользовательские сообщения, комментарии
и документацию сделать русскими.

## 7. Порядок выполнения

1. Зафиксировать текущие контрольные числа и убедиться, что 19 тестов проходят.
2. Создать `common.py` и восемь файлов этапов с `run()`.
3. Сначала перенести расчёты этапов 1–5 без изменения формул.
4. Перенести генератор и анализ сгенерированной выборки.
5. Сделать `main.py` коротким последовательным запуском этапов.
6. Удалить старые универсальные модули и лишние текстовые результаты.
7. Перевести или удалить английские комментарии и docstring.
8. Обновить тесты под новую структуру.
9. Запустить каждый этап отдельно, затем выполнить `python main.py`.
10. Сравнить контрольные числа и изображения с текущей версией и пересобрать
    PDF-отчёт.

## 8. Критерии готовности

Рефакторинг завершён, если:

- каждый этап запускается самостоятельно из корня проекта;
- `main.py` запускает всю работу одной командой;
- в программе нет аргументов командной строки;
- численные результаты варианта 29 не изменились;
- отчёт продолжает находить все нужные таблицы и рисунки;
- отсутствуют английские комментарии и docstring;
- комментарии объясняют только ключевые формулы и решения;
- тесты проверяют формулы, параметры `H2`, воспроизводимость генератора и полный
  запуск программы.
